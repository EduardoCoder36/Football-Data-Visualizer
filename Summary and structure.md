Premier League Trajectory Tracker: Project Summary & Codebase ArchitectureHigh-Level OverviewThe Premier League Trajectory Tracker visualizes and contextualizes a football team’s form throughout the 38-game season. Rather than comparing point totals alone, it plots three trajectory lines for each club to show whether progression stems from genuine improvement or fixture schedule difficulty:  Current Progress (Solid Line): Cumulative points earned across completed matches this season.Last Year’s Pace (Dashed Line): Cumulative points earned at the exact same chronological stage (Matchday $N$) during the previous season.  Same Opponents Comparison (Dotted Line): Points earned last season against the exact same opponent at the exact same venue (Home/Away). For promoted teams that were not in the league last season, a 1-to-1 replacement rule maps them to corresponding relegated clubs (18th place $\leftrightarrow$ Championship 1st, 19th $\leftrightarrow$ 2nd, 20th $\leftrightarrow$ Playoff Winner).  Promoted Clubs: Only display a single line (Current Progress); historical lines are excluded from calculations, charts, and tooltips.  Technical Architecture & File MapPlaintextfootball-tracker/

File Responsibilities1. Database & Security Layer (Supabase PostgreSQL)teams: Stores metadata (ID, name, short name, TLA, crest URL, is_promoted).  fixtures: Completed and scheduled match records (home_team_id, away_team_id, scores, status, kickoff).  relegated_replacements: Maps current-season promoted clubs to prior-season relegated clubs to calculate equivalent opponent points.  team_trajectories: Precomputed table indexed by (team_id, season, games_played) storing current_points, last_year_points, and same_opponent_points for low-latency client reads.  Row-Level Security (RLS): Enabled across all four tables with public SELECT policies for anonymous client-side reads.  2. Backend & Ingestion Layer (services/ & types/)types/contracts.ts: Validates upstream match responses, trajectory calculations, and mapping rules with Zod schemas.  types/database.ts: Defines type definitions matching Supabase tables.services/sync-worker/footballDataClient.ts:Fetches match schedules and scores from api.football-data.org/v4.Inspects X-RequestsAvailable and X-RequestCounter-Reset HTTP headers, proactively pausing or handling HTTP 429 backoff delays to prevent quota exhaustion.  services/sync-worker/syncEngine.ts:Upserts newly discovered clubs into teams to avoid foreign key errors.Synchronizes completed fixtures into fixtures.Evaluates chronological completed games (1 to 38).  Matches historical venue/opponent fixtures using relegated_replacements.  Precomputes cumulative point records and upserts them into team_trajectories.services/sync-worker/index.ts: Reads backend environment secrets (SUPABASE_SERVICE_ROLE_KEY) and triggers runSync() for the active and prior season.3.
